`user` and `system` are each the median of their own paired differences, so they need not sum to the total. Marginal CPU is fitted across all three rates (idle cost separated from per-request cost), so it is one value per edge, repeated on each row; Apache's fit is rejected as unphysical (crash recovery makes its CPU per request climb with rate). `Resolved` counts replicates agreeing in sign. Capacity is deliberately absent: the current ladder does not record which resource saturated first, and the bare tiers appear to be origin-bound (see `docs/BENCHMARK_METHODOLOGY.md` §6).
